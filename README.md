# Project to AI

**Project to AI** — утилита, которая собирает контекст вашего проекта в сжатые `.md`-файлы, готовые к отправке в любой чат с ИИ. Нейросеть, получив такой файл (или несколько частей), сразу видит все исходники, структуру и содержимое — и может работать с ними: объяснять код, искать баги, рефакторить, дописывать, переводить, анализировать.

Работает **полностью локально в браузере**. Никаких серверов, регистраций и загрузок — файлы читаются прямо с вашего диска через File API.

---

## Зачем это нужно

Большинство ИИ-чатов не умеют читать папки. Вы либо копируете файлы по одному, либо получаете ответ вида *«пришлите остальные файлы, я не вижу проект целиком»*. **Project to AI** решает это одним перетаскиванием:

- Собирает **все текстовые файлы** выбранной папки (рекурсивно, с сохранением путей).
- Разбивает результат на части так, чтобы каждая влезала в лимит, который вы задали (по умолчанию — **99 МБ**).
- Нумерует части: `project_1.md`, `project_2.md`, …, `project_N__final.md`. Суффикс `__final` — у последней, включая случай, когда часть всего одна.
- Дополнительно в начало каждой части пишет комментарий-маркер — `<!-- Часть 2 из 5 — есть продолжение (часть 3). -->`, а у последней — `<!-- Часть 5 из 5 — ПОСЛЕДНЯЯ, продолжения нет. Не запрашивай следующие части. -->`.
- Файлы, которые **не удалось прочитать** (бинарники, нечитаемые форматы), **не теряются** — вместо содержимого в дамп попадает запись с путём, расширением, размером и пометкой «файл существует, но не передан нейросети».
- Исключает мусорные папки (`node_modules`, `.git`, `dist` и т.п.) — настраиваемым списком.
- Хранит **настройки отдельно для каждого проекта** (по имени корневой папки) — лимит, имя файла, список исключений. Вернулись к тому же проекту — настройки подтянулись.

В итоге вы получаете 1–несколько `.md`-файлов, которые можно приложить к диалогу с ИИ и получить осмысленный ответ по всему проекту сразу.

## Это не только про код

Инструмент **не привязан к программированию**. Он просто читает текстовые файлы и склеивает их в Markdown. Если у вас:

- **Роман или рассказ**, разбитый по главам в отдельных `.md`/`.txt` файлах — закиньте папку, получите один файл со всей рукописью, и нейросеть сможет редактировать, анализировать сюжет, искать несостыковки.
- **Юридические документы**, договоры, заметки, дневники, сценарии, конспекты, наборы промптов, конфиги, датасеты, базы знаний — всё это тоже читается и упаковывается.
- **Смешанная папка** (код + документация + тексты) — тоже без проблем.

Если файл текстовый и читается как UTF-8 — он попадёт в дамп. Бинарники (изображения, архивы, `.exe`) автоматически **пропускаются по содержимому**, но остаются в дампе как запись с путём и пометкой.

## Как запустить

### Способ 1 — просто открыть (быстро, но с оговорками)

1. Скачайте папку с проектом (`index.html`, `app.js`, `styles.css`, `README.md`).
2. Дважды кликните `index.html` — он откроется в браузере по адресу `file:///…`.

> ⚠️ При открытии через `file://` некоторые браузеры (особенно Chrome) могут ругаться на кодировку и хуже сохранять крупные файлы. Если увидите предупреждение на странице — используйте способ 2.

### Способ 2 — локальный HTTP-сервер (рекомендуется)

Нужен любой из вариантов ниже. Откройте терминал в папке с `index.html` и выполните одну команду:

**Python 3** (есть почти везде):
```bash
python -m http.server 8000
Python 2 (если вдруг):

bash
python -m SimpleHTTPServer 8000
Node.js (если установлен):

bash
npx serve .
PHP:

bash
php -S localhost:8000
Затем откройте в браузере:

text
http://localhost:8000/
Серверу не нужен интернет — он просто отдаёт статические файлы локально. Никакие данные никуда не уходят.
